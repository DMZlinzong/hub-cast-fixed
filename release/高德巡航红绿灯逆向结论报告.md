# 高德 9.5.13 自由巡航红绿灯倒计时数据路径逆向报告

（针对哈弗猛龙 Coffee OS 2.8 / Android 9 / 华阳适配共存版实车测试结果）

## 一、实车测试事实（HUD 1.81 CruiseDebug 实测）

- 自由巡航（无目的地）时高德 UI 显示红绿灯倒计时，HUD 不显示
- HUD 收到的广播类型：**10001、60021、10065、12205、10019**
- **60073 从未出现**（诊断日志 `60073×0`）
- 10001 中 `TRAFFIC_LIGHT_NUM:0`（路线剩余红绿灯总数，非倒数）

## 二、真实数据生产与传递路径（字节码证据）

### 2.1 UI 显示路径（高德巡航悬浮窗，实测有效的那条）

数据结构实证（`com/autonavi/amapauto/CameraLightInfo/CameraLightInfo.java`）：

```java
public String toString() {
    return "CameraLightInfo{waitNum=" + a + ", direction=" + b +
           ", status=" + c + ", countDown=" + d + ", showType=" + e + '}';

```

字段语义与巡航倒计时气泡完全对应：`waitNum`=等待轮数、`direction`=方向、
`status`=灯色、`countDown`=**剩余秒数**、`showType`=显示类型；
`CameraLightInfoWrapper` 持有 `List<CameraLightInfo>`（多灯组，对应高德同时显示 2-3 个灯）。

`defpackage/wh0.java`（KEY_TYPE=60073 的 Intent 组装）：


+ `CruiseTrafficLightAuth` 云端授权），Java 层无开关、无设置协议。

协议模型全量检查：存在 `RspTrafficLightsCountdownInfoModel`（80189，仅响应推送），
**不存在** `ReqTrafficLights*` 请求类——第三方无法主动索取该数据。

## 三、结论（按任务书第五节第 5 条）

**Android 9 无 Root 环境下，第三方应用无法安全获取高德自由巡航红绿灯倒计时。**

理由：

1. 倒计时数据由引擎通过 **JNI 进程内回调**直接送达高德悬浮窗 UI
   （`CameraLightInteract` → `nm.o` → `jm.i`），全程无对外接口；
2. 唯一的对外协议出口（80189 → 60073 广播）被引擎层云端授权门禁关闭
   （实车 `60073×0` 实证），该门禁无 Java 层开关、无设置协议；
3. 无 Root 无法注入高德进程或拦截其 JNI 回调；Xposed/Frida 方案违反
   "不依赖 Root"约束且在车机量产系统上不可靠、不安全；
4. 10001/60021/10065/12205/10019 已逐类核对，均不含倒数秒数。

**不交付伪造修复。** 依据任务书"如果不能取得真实数据，不要伪造倒计时或声称修复成功"。

## 四、当前 HUD 1.81 已处于就绪状态

一旦引擎门禁放行（60073 出现），HUD 无需任何更新即可显示：

- 60073 恒解析（灯色 + 红倒数 + 绿倒数 + 方向 + 等待轮数）
- 倒数键名泛化扫描（车机层换键名形态时自动抓取）
- 多灯组连续性锁定仲裁、绿灯 stuck=3 标志值检测、相位推断
- 60 秒过期自动隐藏、路口切换清空（不残留旧倒数）

## 五、用户侧可行的推动途径

1. 检查高德车机版设置中是否有"巡航红绿灯/红绿灯读秒"开关（部分版本打开后会
   写引擎参数并同步云端授权状态）；
2. 联系华阳/长城售后确认该定制版是否下发了 `CruiseTrafficLightAuth` 授权；
3. 更换/升级高德车机版版本（不同渠道包授权策略不同，如官方 amapauto 版）；
4. 高德侧一旦放行，用 HUD 1.81 的诊断日志复核（`60073×N>0` 即成功）。
