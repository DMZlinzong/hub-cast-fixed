## 1.68 更新（空闲状态不再常挂红绿灯）

**问题**：既没导航也没巡航时（如停车等灯、高德空闲），HUD 上会常挂一个红绿灯计时。

**原因**：这版车机高德空闲时 60075 红绿灯广播照样推送，绘制层无条件把灯画出来。

**修复**：数据通道空闲（>15 秒没有任何巡航/导航数据）时，红绿灯、车道、道路名都不画，只保留限速牌；巡航/导航数据恢复后红绿灯自动重现。正常巡航、导航时的红绿灯显示完全不受影响。

## 1.65 更新（绿灯假 3 秒 + 方向箭头错显直行）

1.64 实拍带来两条关键结论，本轮对应修复：

### 绿灯常亮假"3"

实拍证实这版车机绿灯期间 `greenLastSecond` **固定发 3**（绿灯尾提示标志），
只在真正剩 3 秒内才递减 3→2→1。之前把它当剩余秒数显示，绿灯全程假"3"常亮。

- 连续两条同值（不递减）即判定为标志值：不再显示假 3、不再触发黄灯尾；
- 绿灯期间若红倒数 / 通用倒数都没有真秒数，**只画绿灯不画数字**
  （这版车机绿灯期间确实不发剩余秒，倒数只存在于绿灯尾 3/2/1 和红灯全程）；
- 红灯倒数不受影响，绿灯尾 3/2/1 倒数保留。

### 方向全显示直行

巡航 60075 广播的 `dir`（行驶方向）恒 -1（这版巡航不发），之前无方向
一律画直行箭头 + 全归直行一行。改为：

- 圈内箭头三级兜底：dir > lightIcon > **推荐车道方向**（本车拟行方向
  ≈ 高德推荐车道，左转推荐车道就显示左转箭头）；
- 连车道数据都没有时只画灯色圆，不硬画误导性直行箭头。

**说明**：分行显示（直行一行、左转一行）依赖高德逐方向推送 dir 数据，
这版巡航广播不带 dir，数据上只能单行——圈内箭头会跟随推荐车道方向。
若日后确认这版车机在别的键里带方向（诊断行「红绿灯广播60075 完整extras」
可以验证），再补分行映射。

## 1.62 更新（巡航红绿灯修不通的数据通道）

实车反馈：巡航时 HUD 不显示红绿灯倒计时（车机高德自己有显示）。
本轮从数据源、绘制两端各加一层保障：

1. **AIDL 全协议泛化深扫**：巡航时高德不一定发 60075 广播，红绿灯数据
   可能混在巡航信息类 AIDL 协议里（messageType 不含 TrafficLight，
   之前顶层键检查看不到嵌套字段）。现在对所有消息全树递归扫红绿灯
   特异键（trafficLightStatus / redLightCountDownSeconds / greenLastSecond），
   命中即解析，首条命中后锁定来源协议号（与限速深扫同款机制）。
2. **广播触发条件加 waitRound**：任何 extras 带 waitRound（红绿灯广播特有键）
   的广播都按红绿灯消息解析，不再只认 60073/60075 与三个秒数键。
3. **本地倒数**：巡航数据若只推一两次就停，HUD 数字不再冻结——绘制层
   按「收到时刻 + 剩余秒」每秒本地递减到 0；高德持续推送时以推送为准
   （elapsed<1s 时不递减，两种节奏不冲突）。
4. **60 秒过期剔除**：超过 60 秒没刷新的方向行自动消失（绘制侧兜底），
   不会把导航残留的旧灯一直挂在巡航画面上。

**验证方法**：进巡航等到红灯路口，HUD 应出现红绿灯（有方向分行则两行：
直行一行、左转一行）。如果仍不显示，拍一张主界面诊断行（会显示
「红绿灯[…」原始值行），据此确认巡航时这台车机到底发不发红绿灯数据。
logcat 过滤 `HudCast` 看「巡航红绿灯深扫命中」/「红绿灯广播(type=…)」字样。

## 1.49 更新（重要校准版）

本轮找到了同类开源项目 AMap Companion（GPL，针对同一套高德广播数据
长期实测校准）的解析源码，把红绿灯与车道的编码表全部按它重写：

### 灯色编码表修正（根因）

- 实测表：**status 1=红、4=绿、0/2/3/5/6=黄**——不是我们一直假设的
  1红/2绿/3黄！这是历次灯色错乱的真正根因
- 黄灯尾：绿灯只剩 3 秒以内（greenLastSecond=3 且无红倒数，或 1-2 秒）显示黄
- 倒数秒数 = 当前相位剩余秒（redLightCountDownSeconds 各相位都带值）

### 圆内箭头 = 路口行驶方向（dir 编码表修正 + 恢复跟随）

- dir 实测表：**1=左转、2/3=右转、4=直行、5/6=左前斜、7/8=右前斜、
  0=掉头（导航内显示直行）**
- 之前按 GBL 转向表解析是错的：高德直行时 dir=4 被画成「稍左」、
  左转时 dir=1 落到未知——两轮实拍错位全部对上
- 恢复圆内箭头跟随 dir，无数据时直行兜底

### 车道指引修正 + 取消自动消失

- 取消「15 秒无推送即隐藏车道」的限制（按你的要求），车道指引由
  高德清空 / 新数据驱动，不再自动消失
- 字段优先级照搬 Companion：**drive_way_lane_Back_icon（车道箭头位图
  索引，与官方 LaneAction 枚举数值等价）> trafficLaneIcon > trafficLaneType**——
  之前 Back_icon 排在最后，广播 13012 里的真实方向值被 AIDL 退化值压住
- 广播 13012 车道数据优先：10 秒内有过广播数据时，AIDL 退化值不再覆盖
- 诊断行车道段增加 b=（Back_icon 原始值）

## 1.45 更新

### 车道全直行的根因修复

- 根因：这版车机 `trafficLaneType` 取值是 **0**（语义是「无方向信息 /

## 1.34 更新

### 红绿灯闪烁：根因修复

## 1.33 更新

### 手动绘制「点了画不上」修复

- 根因：手动值原先写进 `cardState`，而高德每秒多次推 30407/30424，

## 1.8 重要结论：后台虚拟屏在这台车机已被系统封死

实测日志给出了决定性证据：

```
Permission Denial: starting Intent { ... pkg=com.autonavi.minimap
  cmp=...SplashActivity } from ProcessRecord{... cn.hud.cast/u0a75}
  with launchDisplayId=7
```

含义：这台车机（Android 14 底层的澎湃 OS 车机）执行了「不可信虚拟屏」限制——
**第三方应用创建的虚拟屏上，禁止启动其他应用的 Activity**。
高德是另一个应用，所以永远拉不进去。

这不是 App 的 bug，也没有任何免 root 的绕过方法（该检查在系统服务 ActivityTaskManager
内部，app 层无法跨越）。**结论：后台虚拟屏模式在这台车机上无法使用，请使用前台镜像模式。**

1.8 的应对：

1. 模式默认值改回「前台镜像」，界面标注后台模式的拦截状态；
2. 拉入失败时状态栏直接给出上述明确结论（不再只有一句报错）；
3. **前台镜像模式补上了诊断看门狗**（之前只挂在后台模式上），镜像模式黑屏时
   状态栏会报帧数，能区分两种死法：
   - 录屏 0 帧 → 授权失效，重新点「开始投屏」授权；重试仍 0 帧 = 车机禁止录屏；
   - 录屏在出帧但**画面全黑**（1.8 新增黑帧检测：每 30 帧采样一次全幅亮度，
     连续 3 次 ≈0 判定）→ 车机 secure 屏禁止抓取主屏内容，录屏路线走不通。

## 安装

1. 把 APK 拷到 U 盘，插车机，用文件管理器点开安装。
2. 如果提示「禁止安装未知来源应用」，去 设置 → 安全 → 允许该文件管理器安装应用。
3. 或者用 adb：`adb install -r HUD投屏-1.21.apk`
4. 从旧版升级直接覆盖安装（同包名同签名，配置自动保留）。

> 车机若启用了「仅允许安装应用白名单/商店应用」或做了签名校验，这个自签名包会被拒绝。那种情况只能改用系统签名重签，或在车机开发者选项里关掉校验。

## 裁剪框（前台镜像模式）

- 裁剪框按**主屏分辨率**百分比计算（本车机 1920×1080）。
- 导航和巡航各存一套裁剪框；「按导航状态自动切换」由高德车机版广播驱动
  （手机版高德没有该广播，需手动切）。
- 先用「巡航」档把整屏裁好，HUD 预览会实时显示效果。

## 三个容易踩的点

**① 授权弹窗点了取消 / 过期**：录屏授权一次有效，App 被杀后需重新授权。
状态栏显示「录屏通道 0 帧」时，停止后重新点「开始投屏」。

**② 车机 secure 屏**：如果 1.8 的黑帧检测报「画面全黑」，说明这台车机的
录屏合成输出被系统拿掉了（部分车机为安全禁用 MediaProjection），此时录屏路线也走不通，
需要 root 或系统级方案（如厂商 HUD 数据通道）。

**③ 高德不在前台时画面停在最后一帧**：录屏抓的是主屏合成画面，
高德退后台后主屏没有导航内容，HUD 自然没有导航——这是机制本身，不是故障。

## 已知限制

- 后台虚拟屏模式在本车机被系统拦截（见 1.8 结论），界面保留该模式仅供
  可能放行的其他车机使用。
- 录屏授权、帧率、secure 屏策略依车机 ROM 而异，以 1.8 状态栏诊断为准。
- HUD 掉线自动重连、息屏停帧等行为与 1.0 相同。

## 出问题怎么看

连 adb 后执行：

```
adb logcat -s HudCast
```

所有状态和异常都打这个 tag。
